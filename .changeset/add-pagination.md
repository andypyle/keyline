Add `Pagination`, which moves between the pages of a paged set: Previous, the page numbers and Next, in a `<nav>` landmark named "Pagination" unless given an `aria-label`. The current page is filled and marked `aria-current="page"`. Long ranges collapse into ellipses around the current page, with `siblingCount` (1 by default) pages either side of it and `boundaryCount` (1) at each end, and the number of controls stays the same wherever the current page is, so they don't shift under the pointer. Pages are buttons, or with `getHref`, links. `onPageChange(page, event)` fires either way, so a client-side router can call `event.preventDefault()`. Previous and Next at either end are `aria-disabled` rather than `disabled`, so a button used to reach the last page keeps focus. `page`, `defaultPage` and `onPageChange` support controlled and uncontrolled use. `getPageLabel`, `previousLabel` and `nextLabel` translate the controls. `size` (`sm`, `md`, `lg`) and `radius` match `Button`. On phones, Previous and Next shrink to their icons and every size takes `sm`'s dimensions, so with `siblingCount={0}` the row fits a 320px screen. Stories go in a new Navigation section.
